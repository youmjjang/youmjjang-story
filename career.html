BRA-C07~C08 · CAREER DESCRIPTION

경력기술서

프로젝트와 경험을 자기조절력·대인관계력·자기동기력과 연결하고 상황·행동·결과로 정리했습니다.

GIGANG · 자기동기력

상황초기 구조는 외부 AI·SaaS 접근 이벤트를 수집해 관리자 화면에 위험도를 보여주는 데 집중돼 있었고, 실제 사용자 PC의 행동과 DB 접근 이력을 함께 판단하는 흐름이 충분히 연결되지 않았습니다.행동서버·DB 연동 파트를 맡아 웹 접근 이벤트와 DB 접근 로그를 수집하고 판단 단계로 전달하는 흐름을 구성했습니다. 알려진 SaaS 정책과 로그 상관분석을 먼저 적용한 뒤 필요한 경우에만 AI 위험도 판단을 결합하도록 구조를 보완했습니다. 사용자 PC에서는 웹 접근과 파일 업로드·붙여넣기 시도를 감지해 경고·차단으로 이어지도록 연결하고, 사용자용·관리자용 실행 흐름도 분리했습니다.결과단순 모니터링 화면을 넘어 웹·DB·사용자 단말 이벤트를 함께 보고 Normal·Watch·Critical로 분류한 뒤 경고·차단과 관리자 확인으로 이어지는 흐름을 테스트할 수 있게 됐습니다.

Mini SOC · 자기동기력

상황보안 관제에 관심은 있었지만 로그 수집부터 탐지·알림·보고까지 한 흐름으로 직접 구현한 경험이 부족했습니다.행동Docker와 Nginx로 테스트 환경을 만들고 Python으로 access log의 IP, 요청 경로, 상태코드를 파싱했습니다. HTTP 오류와 IP별 반복 접근을 탐지해 JSON 경보와 incident 기록으로 저장하고, Flask 알림 서버와 Webhook을 연결했습니다. 이후 날짜별 탐지 건수를 Markdown 일일 리포트로 자동 생성하고, 알림 전송 실패가 분석 전체를 멈추지 않도록 예외 처리도 추가했습니다.결과웹 로그 발생 이후 수집·파싱·탐지·기록·알림·보고서까지 이어지는 작은 SOC 흐름을 직접 구현했고, 기능을 단계적으로 확장하며 문제를 수정하는 경험을 쌓았습니다.

R&D 인턴 · 자기조절력

상황입사 초기부터 SW 요구사항 정의서, 시스템 SW 정의서, SOW와 Specification 등 익숙하지 않은 문서를 빠르게 확인하고 POC 결과와 실제 시스템 동작을 비교해야 했습니다.행동기능과 요구사항을 나누어 확인하고 실제 동작과 문서 기준의 차이를 정리했습니다. POC 과정에서 발생한 기능 동작과 오류 현상을 기록하며 원인을 좁히는 방식으로 업무를 따라갔습니다.결과구현 결과만 보는 것이 아니라 요구사항과 실제 동작을 비교하고 근거를 남기는 방식의 중요성을 경험했고, 이후 프로젝트에서도 로그와 결과를 기준으로 문제를 확인하는 습관으로 이어졌습니다.

카페 근무 · 대인관계력

상황새로운 매장 환경에 적응하면서 바쁜 시간대에 동료와 역할을 나누고 고객 응대와 운영 업무를 동시에 수행해야 했습니다.행동업무 순서를 익힌 뒤 새 직원에게 업무를 설명하고, 동료 의견을 듣고 전달하며 매장에서 불편했던 점을 정리해 개선 의견을 제안했습니다.결과장기간 근무를 이어 갔고 업무 수행을 인정받아 점장 제안을 받았습니다. 함께 일한 동료에게 편지를 받은 경험을 통해 설명과 경청이 실제 협업에 미치는 영향을 확인했습니다.

일본 교환학생 · 자기조절력

상황2023년 약 반년 동안 익숙하지 않은 언어·수업 방식·생활 환경에 적응해야 했습니다.행동준비가 완벽해질 때까지 기다리기보다 모르는 일을 직접 시도하고, 막히면 다시 찾아 수정하는 방식으로 학업과 생활을 이어 갔습니다.결과교환학생 과정을 마쳤고 Excel Programming 수업에서 VBA 프로그램을 완성했습니다. 이후 새로운 과제에서도 먼저 시작하고 결과를 보며 수정하는 방식이 습관으로 남았습니다.
