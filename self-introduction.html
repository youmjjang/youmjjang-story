BRA-C07 · SELF INTRODUCTION

자기소개서

먼저 확인하고, 원인을 찾고, 다시 고칩니다

저는 문제가 생겼을 때 오래 고민하기보다 먼저 작동하는 부분을 확인하고, 결과를 바탕으로 원인을 좁혀 다시 고치는 방식으로 일합니다. 최근에는 이 성향을 보안 관제와 로그 분석에 연결해 직접 로그를 수집하고 탐지·알림·정책 적용까지 이어지는 프로젝트를 만들고 있습니다.

첫 R&D 업무에서는 입사 초기부터 SW 요구사항 정의서, 시스템 SW 정의서, SOW와 Specification 등 익숙하지 않은 문서를 빠르게 확인해야 했습니다. 기능과 요구사항을 나누어 정리하고 POC 과정에서 실제 동작과 문서 내용의 차이를 확인하면서, 문제를 감으로 판단하기보다 기록과 근거를 남기는 방식의 중요성을 배웠습니다.

이후 다른 카페에서 근무하며 새로운 환경에 다시 적응했습니다. 처음에는 제 업무를 익히는 데 집중했지만, 시간이 지나면서 새 직원에게 업무를 설명하고 동료 의견을 듣고 매장의 불편한 점을 정리해 개선 의견을 전달하는 역할까지 맡았습니다. 이 경험을 통해 혼자 빠르게 처리하는 것보다 상황을 정확히 듣고 필요한 정보를 정리해 전달하는 과정이 중요하다는 것을 배웠습니다.

다시 보안 분야를 공부하면서는 배운 내용을 결과물로 확인하기 위해 Mini SOC를 만들었습니다. Docker와 Nginx 환경에서 발생한 웹 로그를 Python으로 파싱하고, HTTP 오류와 IP별 반복 접근을 탐지해 JSON 경보, Flask 알림 서버, 일일 리포트로 연결했습니다. 알림 전송 오류가 전체 분석을 멈추게 하는 문제는 예외 처리를 추가해 수정했습니다. 팀 프로젝트 GIGANG에서는 웹 접근과 DB 접근 이력을 수집하고 규칙·상관분석을 거쳐 위험도를 판단한 뒤 사용자 경고·차단과 관리자 확인으로 이어지는 흐름을 구현했습니다. 초기에는 AI 판단 의존도가 높았지만, 알려진 SaaS 정책과 로그 기반 판단을 먼저 적용하고 필요한 경우에만 AI 판단을 결합하는 방향으로 구조를 보완했습니다.

저는 처음부터 모든 답을 알고 시작하는 사람은 아닙니다. 대신 로그와 실행 결과를 확인하고, 무엇이 정상이고 무엇이 달라졌는지 비교하면서 문제의 원인을 좁혀 갑니다. 앞으로도 보안 관제와 로그 분석 업무에서 이상 징후를 발견하는 데서 끝나지 않고, 반복되는 탐지와 대응을 자동화해 실제 운영에 도움이 되는 결과를 만드는 사람이 되고 싶습니다.
